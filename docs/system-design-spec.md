**Шаг 3 из 3:** план → контент → **спека**
**Статус:** черновик к реализации
**Дополняет:** `pm-thinking-coach-spec-v0.2-skill-tree.md`
**Контент:** `system-design-course.md` — 18 блоков, 96 узлов, 159 уроков, 96 упражнений, 36 сценариев, 515 терминов

## 1. Что добавляется

Седьмой домен дерева PM Thinking Coach. Структурно устроен как остальные шесть: области × круги, блоки, узлы, уроки, гейты. Механика разблокировки, скоринга и оценки наследуется из v0.2 без изменений.

| | Основное дерево (v0.2) | System Design |
|---|---|---|
| Источник таксономии | Карта Тихомирова | Оригинальная разработка |
| Структура | 6 доменов × 3 круга | 6 областей × 3 круга |
| Блоков | 18 | 18 |
| Узлов | 71 | 96 |
| Уроков | ~140 | 159 |
| Длина урока | 3–5 мин | 12–15 мин |
| Упражнения | Нет | 96 |
| Диаграммы | Нет | ~150 |
| Глоссарий | Нет | 515 терминов |
| Сценариев гейта | 36 | 36 |

### Инварианты, которые не трогаются

Наследуются из v0.1 и v0.2 без исключений:

1. Сервер владеет score, XP, датой, дельтами навыков и статусом разблокировки.
2. Ключ AI-провайдера не попадает в iOS-клиент. Оценка только серверная.
3. Авторские последствия снимаются снапшотом при сабмите и не зависят от модели.
4. Ровно три корневых таба.
5. Рассуждение весит больше выбора: rationale 45 + communication 15 = 60 против 25 за опцию.
6. Уроки и упражнения — авторский контент. Модель их не генерирует.
7. Минимум 2 сценария на гейт.

### Что не делается

- Четвёртый таб. System Design живёт в табе «Дерево».
- Генерация диаграмм, уроков и упражнений моделью.
- Оценка упражнений моделью. Упражнения формирующие.
- Отдельная подписка или тариф на домен.
- Изменение формулы скоринга гейта.

## 2. Изменения к спеке v0.2

Точечные правки, каждая с обоснованием.

### 2.1 `estimated_minutes` перестаёт быть константой

**Было:** урок 3–5 минут, зафиксировано в §8 v0.2.
**Стало:** свойство контента. Основное дерево — 3–5 минут, System Design — 12–15.

**Следствия для UI:** время показывается на карточке узла и блока; оценка времени блока считается суммой, а не умножением на константу.

**Следствие для расчёта курса:** 159 × 13.5 мин ≈ 36 ч чтения, 96 × 8 мин ≈ 13 ч упражнений, 18 гейтов × ~25 мин с пересдачами ≈ 8 ч. Итого ≈ 57 часов, то есть 3–4.5 месяца при 3–4 часах в неделю.

### 2.2 Восьмая компетенция

**Было:** 7 ключей `skill_deltas` — шесть доменов карты плюс `communication`.
**Стало:** 8 ключей, добавляется `system_design`.

Внутренние шесть областей System Design на дашборд не выносятся: они видны в дереве, а восемь полосок — предел читаемости. Дельты от гейтов System Design идут в `system_design` и `communication`.

**Миграция:** добавление ключа в `SkillScore` и в схему `skill_deltas` в промпте оценки. Существующие записи получают `system_design = 50` как нейтральный старт.

### 2.3 Вход в дерево

System Design открыт с первого дня, независимо от прогресса в основном дереве. Обоснование: фон у людей разный, человек из разработки может начать отсюда.

В UI — рекомендация пройти `D1` (Discovery, junior) сначала. Подсказка, не замок.

### 2.4 Новое правило валидатора

`covered_lesson_ids` гейта не может ссылаться на уроки блоков выше по кругу. Гейт первого круга не требует знания второго.

Проверяется автоматически. Правило выведено при написании контента — в первой партии обнаружилось нарушение.

### 2.5 Обязательное поле `pm_decision`

У каждого узла — одно предложение о том, какое решение принимает продакт. Узел без заполненного поля не публикуется.

Процедурная защита от соскальзывания в курс для инженеров. Применяется к System Design; для основного дерева — рекомендуется, но не обязательно.

## 3. Модель контента

### 3.1 Иерархия

```
SkillTree (system_design)
 └─ Area (6)
     └─ Block (3 на область = 18)          ← единица разблокировки
         ├─ SkillNode (2–6 на блок, 96)
         │   ├─ Lesson (1–2 на узел, 159)
         │   │   └─ Diagram (0–2 на урок)
         │   └─ Exercise (0–1 на узел, 96)
         └─ Gate → Scenario × 2 (36)
GlossaryTerm (515) — плоский справочник, привязан к блоку
```

### 3.2 Урок

Расширяет `Lesson` из v0.2.

```json
{
  "id": "ds1-n1-l1",
  "node_id": "ds1-n1",
  "block_id": "ds1",
  "order": 1,
  "version": 1,
  "title": "Сущности, атрибуты и связи",
  "estimated_minutes": 13,
  "sections": [
    { "kind": "question",  "blocks": [...] },
    { "kind": "cost",      "blocks": [...] },
    { "kind": "substance", "blocks": [...] },
    { "kind": "example",   "blocks": [...] },
    { "kind": "limits",    "blocks": [...] }
  ],
  "key_takeaway": "Схема данных — это карта возможностей продукта…",
  "term_ids": ["entity", "attribute", "relation", "..."],
  "diagram_ids": ["ds1-n1-l1-schema"],
  "exercise_id": null,
  "cross_refs": ["ds1-n4-l2", "ds2-n1-l1"]
}
```

**Шесть секций в фиксированном порядке:** вопрос, цена, суть, пример, границы, вывод. Отклонение — только с обоснованием в комментарии к контенту, проверяется валидатором.

**Блоки внутри секции:** `paragraph`, `list`, `table`, `example`, `callout`, `diagram_ref`, `code`.

**`term_ids`** — термины, впервые вводимые в этом уроке. Клиент подсвечивает вхождения `[[термин]]` в тексте.

**`cross_refs`** — ссылки на другие уроки, упомянутые в тексте. Используются для навигации и для проверки согласованности.

### 3.3 Упражнение

Новая сущность.

```json
{
  "id": "ex-ds1-4",
  "node_id": "ds1-n4",
  "block_id": "ds1",
  "type": "estimation",
  "title": "Прикидка индекса",
  "prompt_blocks": [...],
  "inputs": [
    { "id": "size",  "label": "Размер индекса", "unit": "МБ", "type": "number" },
    { "id": "count", "label": "Обновлений в сутки", "type": "number" }
  ],
  "acceptance": [
    { "input_id": "size",  "min": 100, "max": 1000 },
    { "input_id": "count", "min": 70000, "max": 90000 }
  ],
  "reference_reasoning_blocks": [...],
  "estimated_minutes": 8
}
```

**Три типа в P0:**

| Тип | Ввод | Проверка |
|---|---|---|
| `estimation` | Числа | Попадание в интервал по порядку величины |
| `classification` | Выбор варианта для каждого пункта | Совпадение с эталоном, частичный зачёт |
| `open` | Свободный текст | Не проверяется, показывается эталон |

Третий тип нужен для упражнений вида «напишите раздел спеки»: проверить программно нельзя, а ценность в попытке и последующем сравнении с эталоном.

**Ключевые правила:**

- Упражнения не входят в `final_score` гейта и не начисляют XP сверх урочного.
- Эталонное рассуждение показывается **всегда**, независимо от правильности ответа.
- Кнопка после ответа — «Понятно», а не «Правильно/Неправильно». Упражнение не оценивает.
- Пройденное упражнение не блокирует переход к гейту. Блокируют только непрочитанные уроки.

**Обоснование, почему формирующие:** оценивание упражнений потребовало бы либо изменения формулы скоринга (запрещено §5 v0.2), либо второй шкалы, которую пришлось бы объяснять. Ценность упражнения — в эталонном разборе, а не в баллах.

### 3.4 Диаграмма

Новая сущность. **Схема хранится как структура, а не как изображение.**

```yaml
id: ds1-n1-l1-schema
title: Ядро «Полки»
nodes:
  - { id: user,  type: store, label: Пользователь }
  - { id: order, type: store, label: Заказ }
  - { id: item,  type: store, label: Позиция заказа }
edges:
  - { from: order, to: user, type: data, label: "многие → один" }
  - { from: item,  to: order, type: data, label: "многие → один" }
```

**Восемь примитивов:** `client`, `service`, `store`, `cache`, `queue`, `external`, `boundary`, `actor`.
**Три типа связей:** `sync` (сплошная стрелка), `async` (пунктирная стрелка), `data` (толстая линия без наконечника).

**Правила рендера, обязательные:**

- Слева направо. Пользователь всегда слева, внешние системы всегда справа.
- Хранилища ниже сервисов.
- Постоянство расположения важнее компактности — человек должен узнавать схему, а не разбирать заново.

**Обоснование выбора:** 150 нарисованных SVG разъедутся стилистически, переживут одну смену дизайна и не адаптируются под тёмную тему и размер экрана. Структура рендерится единообразно, масштабируется и правится за минуту.

**Раскладка:** автоматическая по слоям (клиенты → сервисы → хранилища), с возможностью переопределить порядок внутри слоя полем `layer_order`.

### 3.5 Термин глоссария

```json
{
  "id": "primary-key",
  "term": "Первичный ключ",
  "term_en": "Primary key",
  "definition": "Атрибут, однозначно определяющий запись.",
  "block_id": "ds1",
  "source_lesson_id": "ds1-n4-l1",
  "related_ids": ["foreign-key", "surrogate-key"]
}
```

**Правила:**

- Одно предложение определения. Длиннее — значит, это урок, а не термин.
- Английский эквивалент обязателен: без него человек не найдёт материал вовне.
- `source_lesson_id` — урок, где термин разбирается. Из карточки термина есть переход туда.
- Термины уникальны по `id` во всём курсе. При повторном использовании в другом блоке — ссылка на существующий, не дубль.

**Сведение:** 515 терминов сейчас собраны по блокам. Перед реализацией сводятся в единый индекс с проверкой на дубли и противоречия — пункт 2 из списка «до запуска».

### 3.6 Сценарий гейта

Структура из v0.2 сохраняется. Добавляются поля, специфичные для домена:

```json
{
  "block_id": "ds1",
  "covered_lesson_ids": ["ds1-n1-l1", "ds1-n1-l2", "ds1-n3-l1", "ds1-n4-l2"],
  "rubric": {
    "positive_signals": [
      { "text": "Различает отсутствие сущности и отсутствие данных", "lesson_id": "ds1-n1-l2" }
    ],
    "defensible_alternatives": [
      { "option_id": "B", "condition": "…", "full_credit": true }
    ],
    "negative_signals": [...],
    "remediation": [
      { "gap": "Не различает структуру и данные", "lesson_id": "ds1-n1-l2" }
    ]
  }
}
```

`defensible_alternatives` с флагом `full_credit` — формализация правила v0.1 о том, что защитимая альтернатива не получает автоматически низкий балл.

## 5. API

### 5.1 Добавляется

| Метод | Назначение |
|---|---|
| `GET /v1/trees` | Список деревьев с `kind` и статусами верхнего уровня |
| `GET /v1/tree/{kind}` | Дерево целиком со статусами блоков. Заменяет `GET /v1/tree` из v0.2 |
| `GET /v1/exercises/{id}` | Условие упражнения без эталона |
| `POST /v1/exercises/{id}/submit` | Ответ; возвращает результат проверки **и эталон** |
| `GET /v1/glossary` | Все термины с отметками «встречал», фильтр по блоку и поиск |
| `GET /v1/glossary/{id}` | Один термин для карточки |
| `GET /v1/diagrams/{id}` | Структура схемы |

### 5.2 Правила

**`POST /v1/exercises/{id}/submit`** возвращает эталон в любом случае — включая пустой ответ. Это следует из формирующего характера: человек, не знающий, как подступиться, должен увидеть разбор.

**`GET /v1/tree/{kind}`** — миграция с `GET /v1/tree`. Старый путь сохраняется как алиас на `kind=product` на время обновления клиентов, отключается по правилам из `IN2-N2-L2`.

**Диаграммы** отдаются вместе с уроком в `GET /v1/lessons/{id}`, а не отдельными запросами: их 1–2 на урок, и лишний проход по сети на мобильной сети дороже размера структуры. Отдельный эндпоинт — для полноэкранного просмотра из глоссария.

**Глоссарий** кэшируется на клиенте целиком с версией: 515 терминов — около 80 КБ, обновляется редко.

## 6. Интерфейс

### 6.1 Таб «Дерево» получает переключатель

Сегментед-контрол вверху: **«Продукт» / «Системы»**. Два дерева одинаковой грамматики — те же кольца, секторы, статусы.

**Почему переключатель, а не объединение:** 18 блоков System Design не помещаются седьмым сектором в существующее кольцо — сектор стал бы вчетверо плотнее остальных, и карта перестала бы читаться.

**Почему не четвёртый таб:** §24 v0.1, три корневых таба. Ограничение не пересматривается.

Состояние переключателя запоминается между сессиями. При первом заходе — «Продукт».

### 6.2 Экран урока

Отличается от урока основного дерева:

- **Длинный скролл** вместо одного экрана. Индикатор прогресса чтения сверху.
- **Диаграмма** во всю ширину, тап — полноэкранный просмотр с зумом и панорамированием.
- **Термины** подчёркнуты пунктиром. Тап — карточка снизу: определение, английский эквивалент, кнопка «Подробнее» с переходом в урок-источник.
- **Секции** визуально различимы, но без заголовков-названий: «Вопрос», «Цена» — это структура для автора, не для читателя.
- **Вывод** выделен как заключительный блок — именно он проверяется гейтом.
- **Упражнение** в конце, если есть. До него нельзя проскроллить незаметно: отдельный экран-переход.
- **Перекрёстные ссылки** на другие уроки — кликабельны, открываются поверх с возможностью вернуться.

### 6.3 Экран упражнения

- Условие, поля ввода или варианты.
- Кнопка «Проверить» активна при заполненных полях; «Пропустить и посмотреть разбор» — всегда.
- После ответа: результат по каждому полю (в интервале / вне интервала) и **эталонное рассуждение целиком**.
- Кнопка «Понятно», не «Далее к следующему вопросу» — упражнение завершается пониманием, а не счётом.
- Для типа `estimation` результат формулируется как «порядок верный» / «порядок отличается», а не «правильно/неправильно»: цель упражнения — научить оценивать порядки.

### 6.4 Глоссарий

Отдельный экран, доступ из профиля и из любого урока.

- Поиск по русскому и английскому названию.
- Фильтр по области и блоку.
- Отметка «встречал» — термины из прочитанных уроков помечаются автоматически.
- Карточка: определение, английский, связанные термины, переход в урок-источник.

**Почему нужен:** ICP — полный новичок, и в первом же уроке шесть незнакомых слов. Без термин-чипов и глоссария домен для целевой аудитории нечитаем. Это не украшение, а условие работоспособности.

### 6.5 Прогресс

`system_design` добавляется восьмой компетенцией. Шесть внутренних областей на дашборд не выносятся.

## 7. Скоринг

**Не меняется.** Формула из v0.2 §9 применяется без исключений:

| Компонент | Баллы |
|---|---:|
| Работа с доказательствами | 0–15 |
| Качество решения | 0–25 |
| Качество рассуждения | 0–45 |
| Ясность коммуникации | 0–15 |

Порог `passed` — 70, серверная конфигурация. Набрать 70 только за выбор опции невозможно: максимум 25 + 15 = 40.

**Упражнения вне формулы.** `ExerciseAttempt` не участвует в расчёте и не влияет на `BlockProgress`.

**XP:** урок — 10, гейт сдан — 50 + бонус 0–50. Упражнения XP не дают. Обоснование: XP за упражнение создало бы стимул отвечать наугад ради баллов, что противоречит их назначению.

**Промпт оценки** получает дополнительно названия уроков блока — как в v0.2 §15 шаг 6. Ничего больше не добавляется; ограничения v0.1 §13 не трогаются.

## 8. Валидаторы контента

Проверяются при сборке, нарушение блокирует публикацию.

| # | Правило | Уровень |
|---|---|---|
| 1 | `covered_lesson_ids` гейта не ссылается на блоки выше по кругу | Ошибка |
| 2 | Каждый узел имеет непустой `pm_decision` | Ошибка |
| 3 | Каждый гейт имеет ≥ 2 сценария | Ошибка |
| 4 | Каждый positive signal рубрики имеет `lesson_id` из `covered_lesson_ids` | Ошибка |
| 5 | Каждый gap в `remediation` имеет `lesson_id` | Ошибка |
| 6 | Не-эталонная опция сценария стоит ≥ 8 баллов | Ошибка |
| 7 | Все `term_ids` урока существуют в глоссарии | Ошибка |
| 8 | Все `[[термины]]` в тексте есть в `term_ids` урока или введены ранее | Ошибка |
| 9 | Все `diagram_ids` существуют, все `nodes` в `edges` объявлены | Ошибка |
| 10 | Термин определён ровно один раз во всём курсе | Ошибка |
| 11 | Урок содержит шесть секций в правильном порядке | Предупреждение |
| 12 | Все `cross_refs` указывают на существующие уроки | Ошибка |
| 13 | Граф разблокировки ацикличен и достижим из корня | Ошибка |
| 14 | `estimated_minutes` в диапазоне 5–25 для System Design | Предупреждение |

Правило 8 — техническая основа термин-чипов: если термин помечен в тексте, но не объявлен, клиент не сможет открыть карточку.

## 9. Аналитика

К событиям v0.2 §13 добавляются:

| Событие | Свойства |
|---|---|
| `tree_switched` | `from_kind`, `to_kind` |
| `diagram_opened` | `diagram_id`, `lesson_id` |
| `term_tapped` | `term_id`, `lesson_id`, `is_first_encounter` |
| `glossary_opened` | `source` (профиль / урок), `search_query_length` |
| `exercise_started` | `exercise_id`, `type` |
| `exercise_submitted` | `exercise_id`, `type`, `within_range` (bool), `time_seconds` |
| `exercise_skipped` | `exercise_id` — нажали «посмотреть разбор» без ответа |
| `reference_reasoning_viewed` | `exercise_id`, `seconds_on_screen` |
| `lesson_scroll_depth` | `lesson_id`, `depth_bucket` |
| `cross_ref_followed` | `from_lesson_id`, `to_lesson_id` |

**Сторожевые метрики домена:**

- `term_tapped` с `is_first_encounter` — если частота высока и не падает от блока к блоку, глоссарий не работает как обучающий механизм: люди перечитывают одно и то же.
- `exercise_skipped` — если превышает 40%, упражнения либо слишком трудны, либо воспринимаются как необязательные.
- `lesson_scroll_depth` — доля дочитавших до вывода. Ниже 60% означает, что урок слишком длинный.
- `lessons_completed_ratio` на `gate_started` — наследуется из v0.2, ловит прокликивание.

Правило v0.1 сохраняется: свободный текст ответов на упражнения типа `open` в аналитику не уходит.

## 10. Критерии приёмки

### Функциональные

- [ ] Переключатель в табе «Дерево» показывает два дерева; корневых табов остаётся три.
- [ ] System Design открыт с первого дня независимо от прогресса в основном дереве.
- [ ] Диаграмма рендерится из структуры, открывается на весь экран, читается в тёмной теме.
- [ ] Термин в тексте открывает карточку; из карточки есть переход в урок-источник.
- [ ] Глоссарий доступен из профиля, ищет по русскому и английскому, отмечает встреченные термины.
- [ ] Упражнение показывает эталон при любом ответе, включая пустой.
- [ ] Упражнение не влияет на доступность гейта и не начисляет XP.
- [ ] Гейт становится доступен после прочтения всех уроков блока, упражнения не учитываются.
- [ ] Сдача гейта с ≥70 открывает зависимые блоки в той же транзакции, что пишет XP и дельты.
- [ ] Дельта уходит в `system_design` и `communication`, восемь компетенций видны в прогрессе.
- [ ] Выбор опции без рассуждения не даёт проходного балла.
- [ ] Защитимая альтернатива с сильным обоснованием проходит гейт.
- [ ] `sharper_approach` в фидбеке ссылается на конкретный урок блока.

### Качественные

- [ ] Ключи AI-провайдера отсутствуют в iOS-бинаре.
- [ ] API отклоняет доступ к чужому прогрессу и попыткам упражнений.
- [ ] Все 14 валидаторов проходят на полном корпусе контента.
- [ ] Граф разблокировки System Design ацикличен и достижим из `DS1`.
- [ ] VoiceOver читает диаграмму: тип узла, подпись, связи. Схема имеет текстовое описание.
- [ ] Все 18 блоков имеют уроки, упражнения и минимум по 2 сценария, прошедших QA.
- [ ] 515 терминов сведены в единый индекс без дублей и противоречий.
- [ ] Каждый из 36 сценариев имеет 3 QA-фикстуры: сильную, слабую, защитимую альтернативу.

**Доступность диаграмм** — отдельный пункт: схема как структура даёт возможность сгенерировать текстовое описание автоматически, и это преимущество над картинками стоит использовать.

## 11. Порядок сборки

Вертикальными срезами, поверх v0.2.

1. **Примитивы схем.** Библиотека из 8 элементов и 3 типов связей, рендер из структуры, раскладка по слоям, тёмная тема, текстовое описание для VoiceOver. **Делается до всего остального** — иначе схемы разъедутся.
2. **Глоссарий.** Сущность, сведение 515 терминов в индекс, экран, поиск, карточка, отметки «встречал».
3. **Урок System Design.** Расширение `Lesson`, шесть секций, термин-чипы, встраивание диаграмм, перекрёстные ссылки, индикатор прогресса чтения. Залить блок `DS1` целиком.
4. **Переключатель деревьев.** `SkillTree.kind`, `GET /v1/trees`, `GET /v1/tree/{kind}`, сегментед-контрол, миграция старого эндпоинта.
5. **Упражнения.** Сущность, три типа, экран, проверка интервалов, эталонное рассуждение, аналитика.
6. **Гейт.** Подключение существующего flow к блокам System Design, `defensible_alternatives` с `full_credit`, ремедиация со ссылками на уроки.
7. **Восьмая компетенция.** Миграция `SkillScore`, схема `skill_deltas`, дашборд.
8. **Валидаторы.** Все 14 правил в конвейер сборки контента.
9. **Контент.** Остальные 17 блоков вдоль ствола `DS → IN → SC → PF → AI → SE`, затем средние и внешние круги.
10. **QA и приёмка.** 108 фикстур, прогон оценщика, доступность, чек-лист §10.

**Готово к демо:** блок `DS1` с диаграммами, глоссарием, упражнениями и одним гейтом; переключатель деревьев работает.

**Готово к бете:** внутренний круг всех шести областей — 6 блоков, ~30 узлов, ~50 уроков, 12 сценариев, — плюс полный глоссарий и все валидаторы.
